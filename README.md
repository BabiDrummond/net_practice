# NetPractice

## Description

**NetPractice** is a networking training project from the 42 curriculum focused on understanding and configuring computer networks.

The goal of the project is to develop a practical understanding of how devices communicate over a network by solving a series of networking exercises. Each level provides a network topology containing hosts, routers, switches and connections that must be correctly configured by assigning appropriate IP addresses, subnet masks, gateways and other network parameters.

Through the different levels, the project covers fundamental networking concepts such as:

* IPv4 addressing
* TCP/IP networking
* Subnet masks and CIDR notation
* Network and broadcast addresses
* Host address ranges
* Default gateways
* Routers and switches
* Communication between hosts on the same network
* Communication between different networks
* Routing
* Network interfaces
* Basic OSI model concepts

The project consists of **10 networking levels**, with each level requiring the network configuration to be corrected according to the given topology and constraints.

NetPractice is provided as a training interface and does not require compilation or installation.

1. Download the file provided on the project page.
2. Extract the downloaded files into any directory.
3. Open the `index.html` file in a web browser.

For example:

```text
net_practice.1.7/

```

Opening `index.html` launches the **NetPractice** training interface.

### Training Interface

The interface provides two ways to practice:

* **Personal configuration:** enter your 42 login to practice using your personal configuration.
* **Evaluation:** use the `evaluation` tab to generate a random configuration suitable for evaluation.

The project contains **10 levels**, each representing a networking exercise.

For every level, a non-functioning network diagram is provided together with one or more goals. The objective is to modify the available configuration until the network functions correctly.

The interface provides the following controls:

* **Check again** — verifies whether the current network configuration is correct.
* **Get my config** — exports the current configuration to a file.

The logs displayed at the bottom of the interface can also be used to identify configuration errors, such as missing gateways or invalid IP addresses.

## Resources

### TCP/IP Addressing

An IPv4 address identifies a network interface using 32 bits, normally represented as four decimal octets:

```text
192.168.1.10
```

An IP address is divided into a **network portion** and a **host portion**, according to the subnet mask.

### Subnet Mask

The subnet mask determines which part of an IP address identifies the network and which part identifies the host.

For example:

```text
IP address:  192.168.1.10
Mask:        255.255.255.0
CIDR:        /24
```

A `/24` network provides 256 total addresses, including the network and broadcast addresses.

### Network and Broadcast Addresses

For a network such as:

```text
192.168.1.0/24
```

the network address is:

```text
192.168.1.0
```

and the broadcast address is:

```text
192.168.1.255
```

Normally, usable host addresses are:

```text
192.168.1.1 - 192.168.1.254
```

Understanding these ranges is essential for solving the NetPractice levels.

### Default Gateway

The default gateway is the router interface that a host uses when communicating with a destination outside its local network.

For example:

```text
Host IP:       192.168.1.10
Subnet mask:   255.255.255.0
Gateway:       192.168.1.1
```

The gateway must belong to the same local network as the host.

### Routers

Routers connect different IP networks and forward packets between them.

A router can have multiple interfaces, with each interface belonging to a different network.

For example:

```text
192.168.1.0/24
       |
   [ Router ]
       |
192.168.2.0/24
```

Routing allows a host on one network to communicate with a host on another network.

### Switches

Switches connect devices within a local network. They operate primarily at **Layer 2 of the OSI model**, forwarding Ethernet frames based on MAC addresses.

Unlike a router, a basic switch does not normally connect separate IP networks by itself.

### OSI Model

The OSI model provides a conceptual way to understand network communication:

| Layer | Name         | Example                           |
| ----- | ------------ | --------------------------------- |
| 7     | Application  | HTTP, DNS                         |
| 6     | Presentation | Data representation               |
| 5     | Session      | Sessions                          |
| 4     | Transport    | TCP, UDP                          |
| 3     | Network      | IP, routing                       |
| 2     | Data Link    | Ethernet, MAC addresses, switches |
| 1     | Physical     | Cables, signals                   |

NetPractice focuses mainly on concepts related to **Layer 3 (Network)**, while also requiring an understanding of **Layer 2 (Data Link)** and how network devices interact.
